## Architecture

Single Next.js 15 app (frontend + API routes). Vanilla JS, Tailwind. No separate Express service.

- Browser uses `window.ethereum` (ethers v6 BrowserProvider) for wallet connect.
- Server-side route handlers (`src/app/api/...`) wrap RPC reads (`tokenURI`, `tokenHTML`, `balanceOf`, `tokenOfOwnerByIndex`) so the RPC URL stays out of the client and we cache aggressively.
- Default `RPC_URL = https://ethereum.publicnode.com`. Swap to Alchemy via env var if rate-limits bite.

Terraforms contract: `0x4E1f41613c9084FdB9E34E11fAE9412427480e56`.

## State machine (page.js)

```
phase: idle → walletConnected → parcelSelected
walletAddress, parcels, selectedTokenId, animData, params, error
```

Knob changes update `params`, which trigger a memo'd `generateMandala()` and update the URL via `history.replaceState`. URL params: `?token=<id>&seed=<str>&variance=<1-4>&peak=<1-9>&start=<0-9>&order=<2|4|8>&min=<0-9>&algo=<classic|temple|rings|glyphs>&ring=<concentric|wheel>&rings=<2-20>&terraces=<2-12>&style=<cathedral|wat|ziggurat>&spokes=<1-5>&twist=<0-5>&spin=<cw|ccw>&glyph=<hieroglyphs|nazca|mathcastles>&line=<0-9>&edge=<0-9>&ground=<0-9>&pupil=<0-9>&figure=<horus|ra|ankh|moon|frog|hummingbird|monkey|spider|condor|p1955|p7341>&grain=<0|1>&escher=<design id>&tones=<h1,h2,…>&renderer=<v0|v2>&antenna=<on|off>&exp=<design>&shift=<0-7>&flow=reverse&bg=ground&seal=<commitment|sealed|inscription|list>&salt=off&layout=<flower|eighth|quarter|pinwheel|mirror|rotation|plain>` (layout default flower since 2026-11-19; it was eighth) (`algo` also takes `escher`, `experimental` and `seal`; `glyph=horus` and `eye=` are read for old links only; `figure` is written only when it isn't its set's first, `tones` only when they differ from the design's defaults). `accountsChanged` listener mirrors the Estimator's pattern.

## Encoding (the load-bearing technical detail)

Heightmap is 1024 chars (digits 0–9), arranged as 32 rows × 32 cols (row-major). Each `uint256` covers 2 consecutive rows, read as one **64-digit DECIMAL number**, top-left first; the renderer recovers cells by repeated mod 10 over the zero-padded digits, so leading zeros may vanish from the number harmlessly. `encode()` returns the 16 digit strings; `toCanvasUints()` turns them into BigInts.

**Not hex.** An earlier version of this file said each digit was a hex nibble and to prefix `0x`; that is wrong and decodes to a different heightmap. Verified 2026-10-04 three ways: the contract source comment (`TerraformsDreaming.sol`), the stored canvas of committed parcels #117/#871 (clean digit rows in decimal, noise in hex), and a round trip of a random asymmetric heightmap through both renderers' `tokenHeightmapIndices` (1024/1024 cells; the hex form fails). The copy box was always correct because it shows the bare digits, which Etherscan reads as decimal.

## Onchain actions

Exactly one, added 2026-10-04 at James's explicit request: committing the current mandala with `Terraforms.commitDreamToCanvas(uint256 tokenId, uint256[16] dream)` (selector `0x502f260c`, from the verified source on Sourcify) via `src/lib/commit.js` and `CommitPanel.js`. The site was read-only before this because of the blast radius if it were ever compromised; this path is kept narrow for that reason — no value is sent, no approvals, nothing that can move a token. Worst case for a compromised site is committing a different heightmap to a parcel the user owns.

Before signing, `prepareCommit` checks: minted id, 1024-digit heightmap, mainnet, owner or authorized dreamer, status % 2 == 1 (the contract's require), that BOTH renderers decode the uints back to the exact heightmap, and a simulated `eth_call` from the user's address. `sendCommit` re-checks chain and signer right before signing, then `assertCommitTransaction` checks the exact transaction handed to the wallet: Terraforms address, selector `0x502f260c`, 548 calldata bytes, no ETH, and arguments that decode to the checked tokenId and uints. That last check matters because Terraforms has a payable `fallback()`: a wrong selector would silently succeed and do nothing, and so would its simulation. `verifyCommit` reads back status and all 16 stored uints.

Audit (2026-10-05): the Sourcify source is an exact creation + runtime match, the contract is not a proxy (EIP-1967 slots empty, no delegatecall), and admin functions (pause, early, mintpass, withdraw) cannot touch commits. commitDreamToCanvas writes only `tokenToDreamer`, `tokenToStatus` (+1) and `tokenToCanvasData`, and emits `Terraformed` — no external calls, no ETH, no transfers, no other token affected. **Second write path, added 2026-10-05 at James's request: migration to the v2 renderer.** The commit requires the parcel to render with the renderer the preview showed (`tokenToURIAddressIndex[id]`: 0 = v0, 2 = v2); until 2026-11-17 only v2 was allowed (James 2026-11-17: some owners want to keep creating in the v0 style). On a mismatch the panel offers the preview in the parcel's own renderer (`CommitError.showRenderer`) and the switch to the preview's renderer (`CommitError.migrateTo`: 'v2', or 'v0' — see the switch back below; `needsV2` is a getter for `migrateTo === 'v2'`). v1 (index 1, 0xB51A…5bA5) can't be previewed (its HTML differs from v2's; it draws pixel-identically to v2 only while the parcel's antenna is off, because v1 has no antenna), so v1 parcels are offered the switch to whichever renderer is previewed. Tests: ~/ops/mandala-tx-tests/test-v0.mjs (read-only, mainnet) and ui_v0.py (click-through against a local build, a stand-in wallet that refuses to sign). That mapping is private; it is read from storage slot **11128** (verified on six parcels against which renderer reproduces the contract's own `tokenHTML`). If not on v2, the panel offers `setTokenURIAddress(uint256[] tokens, uint256 index)` (selector `0x29fdf854`) for that ONE parcel with index 2. `prepareMigrate` checks: mainnet, the connected wallet is the actual owner (the contract requires ownerOf; an authorized dreamer is not enough), `tokenURIAddresses(2)` still equals the expected v2 renderer (the contract owner can append renderers), the parcel is not already on v2, and a simulated call. `assertMigrateTransaction` refuses anything but: Terraforms address, that selector, exactly 132 calldata bytes, one tokenId = the parcel, index 2, no ETH. `verifyMigrate` reads the slot back **at the mined block** — that is the decisive check. Comparing the parcel's `tokenHTML` with the v2 renderer's output is best-effort only: generating HTML costs ~9–10M gas for many parcels and >30M for some (#5257), which RPC nodes often refuse for a read, and on 2026-10-05 that made James's successful #9230 migration look failed. Both read-backs are pinned to the receipt's block (a wallet node a block behind otherwise reads the old state), and a read-back problem after a successful receipt is reported as "succeeded, could not double-check", never as a failure. setTokenURIAddress writes only the renderer index (no ETH, no transfers, reversible).

**The switch back to v0, added 2026-11-17 at James's request** (owners who want to create in the v0 style; most dreaming parcels had already migrated to v2): the same `setTokenURIAddress` for ONE parcel with index **0**, offered under the v0 preview when the parcel is on v2 (or v1). `prepareMigrate({ to: 'v0' })` checks the same things as the migration with slot 0 (`tokenURIAddresses(0)` must be the v0 renderer — the array is append-only, so it always will be). The targets live in the frozen `SWITCH_TARGETS` (v0 → 0, v2 → 2); `sendMigrate` and `assertMigrateTransaction` refuse a prepared switch naming any other target or an index that doesn't match its target, and the transaction must carry exactly that index. The confirmation warns that v0 predates antennas: an antenna that is on stops showing and the Antenna and Version traits leave the metadata until the parcel is back on v2 (checked on #7384). Gas ~28k (the slot is zeroed). Proven 2026-11-17 (~/ops/mandala-tx-tests): test-assert.mjs 160/160 (4 byte-level checks × own tx, 3 other kinds and 29 hostile transactions; tampered prepared objects; a source scan that the only wallet writes are the three `signer.sendTransaction` calls in commit.js, each directly behind its byte-level check); test-v0.mjs 22/22 read-only on mainnet; test-switch-fork.mjs 42/42 on a Hardhat mainnet fork through the site's own code — an opcode trace of the switch shows exactly one SSTORE (`tokenToURIAddressIndex[id]`), no LOG, no CALL of any kind, no CREATE/SELFDESTRUCT, owner/approvals/status/canvas unchanged, tokenHTML then equals v0's; strangers, authorized dreamers, index 3 and batches with another owner's parcel revert; ui_switch.py: the click-through switch + v0 commit on the fork, where the preview shown before signing equals the parcel's tokenHTML after, byte for byte; ui_v0.py on mainnet (read-only).

**Third write path, added 2026-11-10 at James's request: return to daydream.** Owners who want to replace a drawing (their own mandala, or a non-mandala heightmap from elsewhere) had to call `enterDream` on Etherscan. When the commit checklist finds the parcel Terraformed (2) or Origin Terraformed (4) and the connected wallet is the OWNER, the panel offers `enterDream(uint256 tokenId)` (selector `0xd359fc19`, present in the deployed bytecode) as its own transaction with the same stages (mode `dream`), then reruns the commit checks. Contract behaviour (TerraformsDreaming.sol): owner only (an authorized dreamer is not enough); status 2 -> 1, 4 -> 3; records the block and emits `Daydreaming`; no ETH, no transfers. While dreaming the renderers ignore the stored canvas (every cell reads 0, a blank canvas; checked on #8776 with `tokenHeightmapIndices`), so the confirmation says the drawing stops showing until the next commit. **On a Terrain parcel (0) enterDream is a permanent mode change; the site never offers or sends it there:** `prepareDream` refuses anything but status 2/4, and `sendDream` re-reads the status right before signing and refuses if it changed. `assertDreamTransaction` refuses anything but: Terraforms address, that selector, exactly 36 calldata bytes, tokenId = the parcel, no ETH. `verifyDream` reads the status at the mined block. Tested 2026-11-10: 16 read-only checks against mainnet (refusals for Terrain, Origin Daydream, non-owner, unminted; six tampered transactions) and a full click-through on a Hardhat mainnet fork as #8776's owner (revert, then commit, both verified).

Do not add other write paths (antenna, transfers, enterDream on a Terrain parcel) without an explicit ask; the antenna page still links to Etherscan. Seals (2026-11-17) add none: a sealed drawing is committed through the same commitDreamToCanvas path and checks as any mandala.

## Contracts (`contracts/`)

`TerraformSealReader.sol` (James 2026-11-18: "put the encoding/decoding onchain ... zero external dependencies ... the same durability as terraforms itself"; one contract): the on-chain seal reader — decode, textOf (inflates DEFLATE), open (HKDF-SHA256 + AES-256-GCM), verifyHash / verifyCommitment / verifyListItem, encode / encodeHash / encodeInscription, spec. Not part of the Next build; James deployed it himself with `contracts/deploy.html` (step by step in `contracts/README.md`; see Deployed below). Run the full suite with `node run-parts.cjs`, never `node test-full.cjs` alone: Hardhat 2.22's EVM (EDR 0.8) keeps every executed step of every call in native memory until the process exits (neither GC nor `hardhat_reset` frees it), so one process of the full suite grows past 9 GB; the runner chains short processes under a 1 GB budget and kills one at 9 GB. The same leak grows the fork node (`hardhat node`) through the UI suites: ~/ops/mandala-tx-tests/run_all_ui.sh gives each suite a fresh node and site (`run_guarded.py`). seal.js and the contract share one limit: a compressed text inflates to at most 64 KiB (`MAX_INFLATED`). The costliest read is under 8M gas (`open` 7.7M; the worst 414-byte DEFLATE payload inflates in 3.9M).
